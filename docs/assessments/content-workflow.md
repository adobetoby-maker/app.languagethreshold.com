## Listening clips

Authored assessment clips use the private `assessment-listening-private` bucket, with a 4 MiB limit and WAV/MP3/Ogg types. A restrictive policy denies direct anonymous/authenticated read, write, list and signing even when unrelated permissive policies exist. The service proxy authorizes the learner's own active, unsubmitted attempt and exact frozen item, checks the bucket is private, then verifies the clip's size, file signature and SHA-256. It returns no-store audio bytes without exposing an object URL. Team admins cannot play a learner's unanswered listening item. Content reviewers use the existing exact-track permission/exposure checks before playing attached clips.

Upload an authored clip outside the public repository with `node scripts/import-assessment-audio.mjs /absolute/private/clip.wav`. This accepts no learner recordings, uses the existing project credentials in memory and never overwrites an object. Copy its `audioAsset` metadata into a **new version** of the private draft form. Its content hash and metadata are covered by the form-review fingerprint. Uploading is neither review nor publication. Reviewers must listen to the attachment, check its transcript, language, clarity and equivalent difficulty, and record their own findings. A missing clip is visible in content review and blocks an official form at application start. QA pilots retain their explicitly labeled device-voice fallback; official attempts do not use it.

The learner fetches each playback with authentication and keeps the Blob URL in memory only, revoking it on completion/unmount. Listening requires connectivity in this phase. Unavailable or incomplete playback remains not assessed. This is authored listening delivery only: protected learner speech, consent, retention/cleanup and recording review remain separate unfinished work. No actual content clip or human review has been supplied by the agent.

## Learner-selected support goals

Learners may choose up to three optional goals and an offline preference for a specific personal/team primary plan. Personal choices stay private; team-plan choices are visible to that team's authorized admins. An admin cannot write the learner's goals. Saved choices have revision checks, retry deduplication and an audit event. Clearing goals or changing interests does not silently replace work, revise lesson mastery or withdraw an already approved supporting assignment.

Reviewed support mappings can declare `goal_tags` using the six keys in `src/lib/assessments/goals.ts`. Existing mappings default to no goal tags. Verified mappings remain immutable: goal coverage requires a newly reviewed mapping version. Goal matches still require the correct language pair, verified lessons and three module exams, reviewed targeted checks where relevant, demonstrated prerequisites, current access and no duplicate enrollment. Already demonstrated units are excluded; full-module suggestions compare demonstrated coverage with all curriculum lessons. Explicit offline preference affects ranking only when offline readiness is verified.

A goal-based suggestion stores a snapshot of the learner's choices and revision, `basis=learner_goal`, no source assessment and an empty scored-evidence list. It never invents a weakness or a score. Assessed-gap suggestions retain their original recent-calibrated-evidence requirement. The two paths share the two-suggestion limit, explicit independent/admin approval, one active support assignment, study-time budget and targeted/full-module follow-up schedules. A pending goal suggestion must be reviewed again after goals change; approved history retains its original basis. Actual catalog mappings remain unreviewed and are not made eligible by selecting an interest.

## Protected learner speech — backend checkpoint

An inactive media-policy row and the private `assessment-speech-private` bucket now support the protected evidence backend. **Collection and cleanup are both disabled.** No policy approval was recorded. The pending version is not a consent notice that enables recording. An actual approved notice/retention version must be supplied before either switch can be enabled; an approved notice, approval identity and retention period are immutable, requiring a new version for changes.

The same-origin authenticated upload handler accepts at most 4 MiB of WebM/Ogg/MP4/WAV, streams with a hard byte limit, checks the file signature and storage round-trip hash, and attaches only to the learner's exact frozen speaking question and current attempt revision. Capture duration is client-reported and bounded to two minutes; it is not represented as server-verified speech duration. Request IDs prevent duplicate attachment; changed payloads conflict. Unfinished uploads remain tracked for later cleanup. No public/signed URL is exposed.

Playback authorizes the current learner or independent response reviewer, requires the attached evidence, verifies bytes and rechecks withdrawal/access after fetching storage. A rubric score for speaking requires ready consented evidence plus that reviewer's explicit listening acknowledgement. Typed transcripts remain insufficient. Withdrawal hides playback immediately without rewriting historical score events.

The cleanup worker defaults to a dry run. Its service-only SQL selector returns no work while cleanup is disabled. With an approved policy, it selects withdrawal requests, orphaned objects, old incomplete uploads and final completed evidence beyond the retention period; unresolved review requests postpone expiry, and dispute resolution restarts the clock. A deleting tombstone blocks playback; removal failures remain retryable, and deletion is recorded only after storage removal succeeds. No cleanup scheduler or production recording UI is activated by this checkpoint.

Local fictional fixtures, all rolled back, exercised positive consent/attachment/review and the retention/dispute/withdrawal lifecycle; fourteen unit boundary tests cover streams, access, corruption, withdrawal races and cleanup failure ordering. The hosted storage trial used only a unique synthetic non-speech file and removed it. Browser capture controls, consent presentation, reviewer playback/acknowledgement controls and final end-to-end acceptance remain the next implementation step.

## Speaking controls and review — staged UI checkpoint

The learner now sees the actual policy gate at each speaking question. When a real policy is enabled, the controls require explicit consent before requesting an audio-only microphone, support stop/cancel and a local preview, and upload only on the learner's command. Collection additionally requires cleanup enabled. A replacement upload withdraws the earlier take. The approved policy/real capture pilot is still pending; both production policy switches remain off.

Unsynced takes live only in an account/attempt/question-scoped memory registry. They survive in-app question remounts, are never put in localStorage/IndexedDB/offline packs, warn on unload/sign-out and are cleared with the account's drafts. Capture tracks stop on stop/cancel/unmount/account change, including recorder startup failure. Submission is blocked until unsynced takes are uploaded or deliberately discarded. A failed upload keeps the Blob and stable request ID; success reloads the authoritative response/revision. Pending edits, uncertain save flights and older server revisions cannot be overwritten by this reload.

Submitted speaking responses expose only a safe availability projection. The learner may play or withdraw an attached recording. Response reviewers listen through the authenticated proxy, can stop playback, and must finish playback and explicitly acknowledge listening before the UI offers a rubric score. Stopping early does not unlock it. The database still enforces the independent reviewer, current exact evidence and acknowledgement checks; unavailable/withdrawn media cannot support a new score. Initial grading labels a server-verified recording Needs review, never an automatic spoken score.
