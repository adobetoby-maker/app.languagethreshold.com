# Core 30 progress context

New practice records belong to a module, target language, instruction language and optional assessment enrollment. Independent practice has its own context. The signed-in profile/device store provides the account boundary. A visit, self-declared mastery, review, plan start and sequential lesson counter must all use the same context. A language change or a different plan cannot inherit those records automatically.

The persisted key is a versioned JSON tuple created by `core30ScopeKey`. Module-only keys remain archived history; they are not deleted or silently assigned to a language or enrollment. The lesson overview offers an expandable history card. A learner must identify the displayed language pair and plan with a checkbox before linking a copy. Linking preserves the original and existing work, records the claim date, and adds no XP, completed-session count, exam score or certificate. The claim is a statement about the learner's own practice history, not evidence of assessed proficiency. The initial link is idempotent. Later writes from an older app remain in the archived record; automatic ongoing reconciliation of that unlabeled history is intentionally not inferred.

Resume positions distinguish enrollment IDs as well as account/module/pair. Independent practice retains its existing position key. Supporting-practice return links read the primary enrollment's own position. Lesson handwriting drafts remain reusable private practice material for their existing lesson/pair context; they are not graded exam responses.

Team reporting reads the organization's actual full-module enrollment rows for active members and assigned modules. It constructs the corresponding keys server-side and returns only summary fields. It excludes personal practice, other organizations' plans and targeted support-unit checks from those whole-module totals. Earlier module-only records remain separately labeled; they are never added to a scoped plan total. Teams without a full-module Exams enrollment retain their earlier summary and legacy activity counters; new independent practice does not automatically become team-plan mastery. Create/link the learner's team exam plan to obtain scoped reporting.

Plan status uses the approved start date, timezone and pause/resume history, matching the existing study-calendar projection. Counts describe participation and learner-declared mastery. Legacy recorded-lesson/certificate counters remain a separate existing subsystem and do not become calibrated Exams results.

New exam attempts derive reported studied objectives only from the matching enrollment/pair log. They do not infer study from a bare module key. This coverage is learner-reported practice evidence, not a scored skill result. Existing saved attempts remain tied to their original snapshots.

Verification must include actual reducer/cloud-merge behavior, a normal learner/admin browser flow, language and plan switching, explicit history recovery, and the absence of private fields in team summaries. An authenticated browser trial and synthetic test records do not replace a real proficiency pilot, physical-device verification or reviewed curriculum release.
