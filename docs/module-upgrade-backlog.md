# Module upgrade backlog

Proposed order, October 15, 2026. This covers all 59 modules in the audited catalog; it is not a rollout-date commitment. Roofing goes first. Subsequent order favors content reuse and must be revised using real learner demand and available domain/language reviewers. Demonstration assignments and certificate fixtures are not demand evidence.

Every row requires 30 coherent lessons; reviewed words, phrases and contextual usage; all six learning modes driven by explicit lesson settings; entrance/day 45/day 90 exams; personal and team verification; accurate offline labels; and owner-reviewed pilot acceptance. A generated deck or completed code change does not close a row.

Initial language track: English instructions → Spanish target, except English-for-work modules, which begin with Spanish instructions → English. Other compatible language pairs remain in the readiness inventory and need their own reviewed content and release records. They are not implicitly verified by this first track.

Content owner role: curriculum lead. Required sign-offs: fluent-language reviewer, domain reviewer, QA, and product owner. Specific people are not yet assigned; that remains a release dependency. Codex owns shared-engine implementation, not human review approval.

Current source audit: fcc6b6e, October 16, after Claude integration. The catalog has 59 modules, 1,510 lessons and 7,076 compatible tracks. Seventeen modules need 260 additional lessons: sixteen travel modules have 15 each, and Sport Fishing has 10. The compact [source inventory](reviews/module-source-coverage-2026-10-16.json) lists every module and its initial track; the complete local artifact includes every compatible pair.

On the initial tracks, shared lesson definitions contain 31 word lists, 31 lesson-specific passages and 30 explicit toolkit settings: Roofing supplies 30 of each, Landscaper supplies one word list and one passage. Construction Foreman also has 30 saved generated lists on its initial target track, which are a different source and do not prove reviewed lesson alignment. Other runtime practice sources may exist. The audit finds 1,059 written lesson plans without an explicit recall/game step; this does not mean 1,059 runtime games are absent. Check the embedded toolkit before labeling an activity missing.

The team Exams readiness inspector now shows actual definition counts, per-lesson gaps and a module picker, rather than fixed Roofing-only counts. The inspector is structural evidence, not a content approval. One release-consistency task remains: unify enrollment availability and new official exam-start checks with the same current-source completeness gate. Do not infer an official release from a readiness card or an existing database status alone.

Release workflow: audit → authored content → six-mode runtime checks → reviewed exam forms and rubric checks → real personal/team integration → owner pilot → versioned release. Supporting recommendations may use only explicitly verified content. Missing eligible support is a curriculum gap, not permission to assign an unrelated module.
