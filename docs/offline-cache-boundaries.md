# Offline shell and private-page cache boundaries

Public lesson packs and private assessment device data use separate stores. A completed Spanish/English Roofing or Landscaper pack contains public lesson content, public app assets and a signed-out root shell. It contains no scored exam keys, learner responses or team/admin pages. Hash verification must finish before a pack earns its ready marker.

The general worker cache is `lt-v15`. Activation removes earlier numbered general caches and retains complete lesson packs. Private content/reviewer, team, owner, account, certificate, family and subscription HTML never enters the general navigation cache. API requests, authorization headers, mutations and other origins bypass it. Ordinary caching honors no-store/private and rejects redirects. Scoped root lessons can fall back to a public shell without caching their identity-specific URL or HTML. Private HTTP responses receive no-store/no-referrer/noindex.

Exams has one deliberate public-bootstrap exception. During first worker installation and after successful controlled online Exams navigation, the worker fetches `/exams?target=Spanish&native=English` with credentials omitted, cache:no-store, no identity/authorization and redirects rejected. Only the signed-out HTML goes under `/.lt-public-exams-shell`; the original private navigation response is never cached. The canonical pair avoids the bare-route redirect. Its authenticated content loads client-side from authorized APIs. A failed public-bootstrap preparation does not fabricate content/results or break the rest of installation.

Previously authorized active attempts and device answers remain private to their account in the existing device store, with bounded snapshots and explicit sign-out cleanup. Recovered UI identifies its saved-device provenance and last confirmed sync. Check server copy loads the current authorized attempt while retaining question position; pending answers, uncertain requests and recordings must be resolved first. Clean drafts adopt fresh server revisions; pending work retains its original base for conflict handling. Acknowledged answer changes are saved with their revision until a fresh server read so a separate snapshot effect cannot be the only copy during immediate reload. Official start/submission still require a connection. Device progress never grants membership, assessment review or proficiency.

Worker protocol2 allowlists roofing-es-en and landscaper-es-en. Install/status/remove requests include exact pack identity; replacements affect only that module, failed updates preserve the previous complete pack, and older Roofing cache names require a validated ready manifest. Another module’s files cannot earn a ready label. The shell fallback prefers the requested supported exact pair. Unsupported module/pair downloads are not offered. App assets are currently included per pack; deduplication is not claimed. Browser storage can be evicted and ready status requires a fresh integrity check.
