# Offline shell and private-page cache boundaries

Public lesson downloads and private assessment data use different stores. A completed Roofing or Landscaper Spanish/English pack contains public lesson content, public app assets and a signed-out root shell. It does not contain scored exam keys, learner responses or team/admin pages. The existing pack installer verifies hashes and commits its ready marker only after the complete public download succeeds.

The general service worker cache is now `lt-v14`. Activation removes earlier numbered general caches and retains complete lesson-pack caches. Private Exams/content/reviewer, team, owner, account, certificate, family and subscription pages do not enter the general navigation cache. API requests, authorized requests, mutations and other origins bypass it. Normal response caching honors `no-store` and `private` and rejects redirected responses. Initial automatic shell caching follows the same policy.

A root lesson URL containing enrollment/team/identity context may fall back to the public app shell, but its identity-specific URL/HTML is not cached. Private page HTTP responses also receive no-store, no-referrer and noindex headers. Server-function retry headers and CSRF behavior remain intact.

Release1 still needs a previously opened exam's account-owned device copy to survive a short offline refresh. On a successful online `/exams` navigation, the worker separately fetches one fixed public bootstrap: `/exams?target=Spanish&native=English`, with credentials omitted, no query identity or authorization, and redirects rejected. Only that signed-out HTML bootstrap is stored under `/.lt-public-exams-shell`. This is a deliberate public-bootstrap copy, not caching of the original private navigation response. The route's authenticated content loads client-side from authorized APIs; its server-rendered signed-out shell contains no attempt responses, private items or answer keys. Actual attempts/responses remain in the existing account-owned device store. Official start and submission still require a connection. A missing public bootstrap cannot become a fabricated assessment result.

The canonical pair is required because bare `/exams` redirects to add default language settings. Hosted checks verify both normalization and the canonical private response headers. The saved public shell must be browser-tested with actual context restoration before offline refresh acceptance is claimed.
