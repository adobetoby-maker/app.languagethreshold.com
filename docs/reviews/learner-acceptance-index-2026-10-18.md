## Main-profile recovery boundary

`legacy-profile-recovery.ts` imports only a validated allowlist from the highest present `lt.app.v2`, `lt.app.v1` or `lt.app` source. The account must finish its current profile restore and explicitly confirm ownership. Personal notes merge by ID with current values retained. Vocabulary preserves known language labels, requires a language choice for unlabeled words, retains current translations/mastery and explicit empty revisions, and increments revisions for additions. Activity counters use max, never a sum; streaks are excluded. Bare module history stays an owned archive until the existing learning-guide language-pair confirmation; enrollment-linked records are not transferred. Purchases, assignments, proficiency declarations, settings and exam results are excluded.

The original source bytes remain. The first claim reserves the whole old profile for one account, with per-category completion receipts and guarded same-account retry on storage failure. Current invalid destination envelopes are not overwritten. Saved patches update the actual pure reducer without a reload race. The account provider subsequently attempts its existing normal cloud sync; device persistence is not proof of cloud backup. Exam pages without the profile provider offer a separate learning tab. The dialog now scrolls within the viewport, but actual phone/browser acceptance is still open. The earlier index JSON is an audit of the prior source, not current implementation proof.

Qualified content/reviewer decisions, calibrated/equivalent forms, real consented personal/team pilots, physical-device/audio, owner retention, installed cleanup scheduling and full companion/shared-auth acceptance remain release gates.
