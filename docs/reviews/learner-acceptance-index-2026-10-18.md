## Main-profile implementation boundary

The current profile persists private notes, vocabulary, practice counters and language/enrollment progress alongside fields such as purchased modules, assignments and earlier CEFR completion declarations. Reusing the existing broad profile migration or `MERGE_REMOTE` action directly on unassigned legacy data is not a validated recovery contract. The existing account profile also syncs to cloud after restoration, whereas the practice-category recovery dialog promises browser-only saves.

The next implementation should therefore define validated categories and their exact merge/sync behavior before wiring the UI: preserve original bytes, reserve ownership for one account, keep current items and explicit resets, avoid adding overlapping XP/streak totals, and require an explicit language/enrollment destination for ambiguous progress. Unknown legacy fields must not become current entitlements, assigned work or demonstrated proficiency. This is an implementation task within the authorized recovery scope, not a request for a new policy approval. Populated normal-UI acceptance remains required after implementation.

Qualified content/reviewer decisions, calibrated/equivalent forms, real consented personal/team pilots, physical-device/audio, owner retention, installed cleanup scheduling and full companion/shared-auth acceptance remain release gates. The prior retention question remains pending and must not be repeated or treated as approval. Speech collection and scheduling remain off. No new browser, provider, account-data or production action was taken for this index.
