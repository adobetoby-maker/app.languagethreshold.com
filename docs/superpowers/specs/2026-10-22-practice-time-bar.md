# Practice time bar

Owner request (2026-10-22): a thin progress bar that builds left to right so learners can see their work. Owner chose **today's practice time**, toggled **on/off in settings**, shipped **after the Friday demo** (branch only until then).

## Behavior
- 3px bar, gold accent (`bg-gold` / existing token), track at low-opacity border color. Fills left to right with today's active practice time / daily goal.
- Placement (after main's navigation change): the phone's primary nav (`AppSidebar.tsx`, `fixed`, now `desktop:hidden`) and the desktop `TopNav` header (`sticky`) are the persistent app bars. `<PracticeTimeBar edge="nav" />` sits on the nav's top edge, `<PracticeTimeBar edge="header" />` on the header's bottom edge, both absolute (no added height). Only the one matching the `desktop` media query renders, so the page holds exactly one bar. `<PracticeTimeTicker />` is mounted once in `AppSidebar` and owns the single 1s ticker.
- Settings: main moved device preferences to the phone "App settings" sheet (`AppSidebar.tsx`) and the desktop "Learning settings" popover (`TopNav.tsx`). `PracticeBarSetting` (switch, daily goal, "Today: N of M min") sits in both; the Dashboard card is gone.
- `AppGuide.tsx`: "How Core 30 works" is read in render and spent in an effect. The old render-phase `removeItem` lost the request when React retried a discarded render, which the once-a-second bar updates exposed (core30-plan 7d).
- Counting: idle counts while `now - lastInteraction < 60s` (exactly 60s idle stops). The interaction clock starts at app load. No counting while the bar is switched off. A learner must act once after load before any second counts (the interaction clock is module-level and starts empty, so remounts earn nothing). While `SubscriptionGate` shows a blocking screen (paywall overlay, missionary inline reminder, Foundation sign-in prompt) it renders `<PracticeBlocker />`; the bar is hidden and the ticker does not count. The gate still renders children blurred under the paywall, so the blocker, not unmounting, is the signal.
- Goal clamp snaps to the nearest of 5/10/15/20, ties go lower, junk becomes 10. Prune keeps today plus the 13 days before it.
- Cross-window: a re-read (tab visible, `storage` event) merges storage into memory taking the max seconds per day; settings come from storage. A failed read never wipes in-memory data.
- Goal pulse is a single Web Animations opacity pulse, only when one ticker beat (+1 second, same goal) crosses the goal; never on the first client value, a reload or a goal change; skipped under `prefers-reduced-motion`.
- Track is `bg-foreground/25`. The bar stays `pointer-events-none` with no tooltip.
- The e2e spec seeds its own state and needs no `setup` project; run it through `scripts/with-supabase-public-env.mjs` or the app hangs on loading.

## Decisions: lesson goal

Owner request (2026-10-24): "give the goal a lesson goal as well". Owner chose **choose minutes or lessons** in settings: minutes per day (the shipped bar) or lessons per day. The same thin bar fills toward whichever goal is chosen.

- Settings (`PracticeBarSetting`, phone "App settings" sheet and desktop "Learning settings" popover): a two-option radio group "Daily goal type" (Minutes / Lessons, Radix radio group: arrow keys, `role="radiogroup"`). Minutes keeps the 5/10/15/20 select; Lessons offers 1, 2 or 3 lessons per day (default 1). Status line: "Today: 6 of 10 min", "Today: 0 of 1 lesson", "Today: 1 of 2 lessons" (count never shown above the goal, like minutes).
- Storage: same key and `v: 1` record (`lt.practice-time.v1`), two new fields `goalType` ("minutes" | "lessons") and `goalLessons` (1 to 3). A record without them (everything saved by the shipped bar) reads as minutes with a 1-lesson goal, so no learner's bar changes on update. Junk values fall back field by field.
- Lesson signal: **derived from the persisted Core 30/60 log, no new storage and no call-site change.** A lesson counts for a day when its `masteredAt` (ISO time written by `core30SetMastered` when the learner presses "I've mastered this lesson") falls on that local calendar day, any module and language pair. The log keeps the earliest `masteredAt`, so mastering again the same day cannot double count and a lesson is not recounted on a later day. Opening a lesson or a step (`visits`, `wayVisits`) counts nothing. Why not `COMPLETE_LESSON` (the sequential counter) or a new per-day set: the counter has no timestamp and `advancePastMastered` fires it for several already-mastered lessons at once, which would credit lessons not done today; a new per-day set would need an emit inside `AppGuide.finishLesson` and would not follow the log across devices. `masteredAt` already syncs through the cloud merge. Lesson counts are computed in `useLessonsToday` (`src/hooks/use-practice-time.ts`) from `state.core30Log`, once the app has hydrated.
- Known edges: "Record lesson N complete" for a lesson mastered on an earlier day is not a new lesson today; re-mastering after a failed review keeps the first `masteredAt` and so does not count again; a lesson mastered on another device today appears after cloud sync (and can fire the goal pulse once if it carries the count across the goal). A legacy bare-module record and its claimed scoped copy count a lesson once.
- Bar: with Lessons chosen, fill = min(lessonsToday / goal, 1). Same 3px bar, placement, `bg-gold`, 400ms ease (none under reduced motion). Hidden-tab and 60s-idle rules apply only to minutes; the ticker keeps counting minutes in the background whatever the type, so switching type is instant and loses nothing. The paywall blocker still hides the bar for both types.
- Pulse: the same single opacity pulse, when one lesson carries today's count across the goal live. Not on first value, reload, hydration, goal change or type change (the previous value is dropped on a type change and until the app state has loaded).
- Accessibility: `aria-label` "Today's practice: 1 of 2 lessons" (minutes unchanged), `aria-valuemax` the goal in lessons, `aria-valuenow` lessons done (capped), and `aria-valuetext` "1 of 2 lessons today" (minutes now also get "6 of 10 minutes today" instead of a raw seconds value).
- Day rollover: the store tracks the local date key (refreshed every ticker beat), so the lesson count resets at local midnight like minutes do.
- Tests: `tests/practice-time.test.mjs` (prefs migration, distinct-per-day counting through the real `core30SetMastered`, day rollover, fill fraction, lessons pulse) and `e2e/practice-bar.spec.ts` (switch to Lessons, labels, persistence across reload, seeded count, and mastering a lesson through the real Core 60 flow filling a 1-lesson goal).
